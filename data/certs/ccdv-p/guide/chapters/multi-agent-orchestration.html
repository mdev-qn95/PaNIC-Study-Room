Key points

  • Start with the simplest pattern and add agents only when evidence justifies the cost, since autonomy trades latency and cost for performance.
  • Agents used about 4x the tokens of chat and multi-agent systems about 15x; the task's value must justify that cost.
  • Decompose by context boundary, not by SDLC role, and keep tightly coupled work in one agent per component.
  • Put mandatory permission checks in PreToolUse hooks: earlier approvals mean a call never reaches canUseTool.
  • State the verification bar in the prompt — full suite, edge cases, negative tests — or it declares success too early.

Multi-agent orchestration is the design work around a lead agent: what it keeps, what it hands off, how the handoffs execute, and what happens when one fails. Anthropic distinguishes workflows, which orchestrate LLMs and tools through predefined code paths, from agents, which let an LLM direct its own process and tool use dynamically. Agentic systems can trade latency and cost for task performance. Start with the simplest pattern that works, often a single augmented LLM, and add agents when evidence justifies the cost. Inter-agent failures include dropped requirements, incomplete verification, and approval gates that never fire.

A supervisor/worker hierarchy has a lead agent delegate tasks to workers and combine their results.

Orchestration patterns and what they cost

These five common patterns can be combined in a supervisor/worker design and implemented without a multi-agent framework.

Pattern Mechanism Use when
Prompt chaining Sequential LLM calls, each processing the previous output, with optional programmatic gates on intermediate steps. Subtasks are fixed, and splitting trades latency for accuracy.
Routing Classify the input, then dispatch it to a specialized follow-up task, prompt, or tool. Input classes need materially different handling.
Parallelization Sectioning runs independent subtasks at once; voting runs the same task repeatedly for diverse outputs or higher confidence. Subtasks are independent, or confidence needs several attempts.
Orchestrator-workers A central LLM decides the subtasks from the input at runtime, delegates to worker LLMs, and synthesizes results. The subtask list cannot be predefined.
Evaluator-optimizer A generator and an evaluator iterate in a feedback loop. Clear criteria exist and refinement adds measurable value.

Cost is measured, not guessed. On Anthropic's internal research evaluation, a multi-agent system with Claude Opus 4 as the lead agent and Claude Sonnet 4 subagents outperformed single-agent Claude Opus 4 by 90.2%. In BrowseComp analysis, token usage alone explained 80% of performance variance; tool-call count and model choice explained much of the rest. Treat those results as evidence to measure token spend alongside topology, not as a guaranteed gain. In Anthropic's data, agents used about 4x as many tokens as chat interactions, and multi-agent systems about 15x. The task's value must justify that cost.

Bounding delegation and context isolation

Delegation is a specification problem before it is a concurrency problem. Prefer to scale agent count and tool-call budget to query difficulty. Give each worker a delegation spec: an objective, output format, tool and source guidance, and explicit task boundaries. Vague task descriptions can cause duplicate work, gaps, or missed information. Bound fan-out with hard caps as well as prompt instructions.

Tool reach decides what a worker may do unattended: AgentDefinition.tools lists allowed tools, and disallowedTools removes tools from that set. MCP server patterns such as mcp__server__* and mcp__* are supported. CLAUDE_AGENT_SDK_DISABLE_BUILTIN_AGENTS=1 removes the built-in fallback; a call without subagent_type then fails. disallowed_tools=["Agent(fork)"] blocks forked subagents while leaving other subagent types available. In Python, AgentDefinition keeps camelCase fields such as disallowedTools, permissionMode, and maxTurns; ClaudeAgentOptions fields use snake_case.

Context isolation decides what a worker knows. A non-fork SDK subagent starts with a fresh context and no parent conversation; pass needed paths, errors, and decisions in its prompt. It returns its final report to the parent. Claude Code can also give a subagent a separate Git worktree with isolation: worktree.

Decompose by context boundary, not by SDLC role. A planner, coder, tester, reviewer chain re-summarizes shared context at every hop, losing requirements and burning coordination tokens; split by context instead — independent search facets, clean API contracts, black-box verification — and keep tightly coupled work in one agent per component.

An artifact store holds large worker outputs outside the conversation; workers return lightweight references. This can reduce information loss and the tokens spent copying results through conversation history.

Second, a verification subagent isolates context well but tests poorly: black-box validation with minimal prior context is its strength, yet the early victory problem makes it run one or two tests, see them pass, and declare success. State the bar in its prompt: full suite, edge cases, negative tests.

Parallel dispatch and critical-path latency

Parallel dispatch can reduce critical-path time: independent subtasks can finish in the time of the slowest one rather than the sum of all of them. By default, background subagents return status: "async_launched"; when the agent waits for a result, the call returns status: "completed". In one Anthropic research system, the lead launched 3–5 subagents in parallel and each used 3 or more tools in parallel. That setup cut research time by up to 90% on complex queries.

Synchronous execution is simpler to coordinate and slower to run: waiting for each wave blocks on the slowest subagent and prevents the lead from steering work already in flight, while asynchronous execution raises concurrency at the cost of state consistency and harder error propagation. Four things flatten the theoretical speedup:

Speedup killer Mechanism Countermeasure
Straggler barrier A synchronous wave waits on its slowest worker or that worker's retry. Async dispatch, priced in state consistency and error propagation.
Mutating-tool serialization Read-only tools (Read, Glob, Grep, read-only MCP tools) run concurrently while Edit, Write, Bash run sequentially; a custom tool joins the concurrent path only with readOnlyHint. Keep concurrent writers on disjoint files or in separate worktrees.
Rate-limit contention Subagent requests count against organization-level API rate limits. Set concurrency from observed throughput and backoff behavior
Repeated context A non-fork subagent starts without the parent conversation. Pass only the context each worker needs; use a fork when the task needs the parent's context.

Inter-agent communication and structured handoffs

Agents communicate by what they hand each other; the mechanisms differ in where loop state and intermediate results live.

Mechanism Topology Where intermediate state lives Hard constraints
Subagents (Agent tool) Hub-and-spoke in one session; only the final message returns. Parent context window, plus the subagent's isolated window Output is scanned for instruction-shaped text before the parent reads it.
Agent Teams Peer sessions share a task list and communicate directly. Shared task list and teammate messages. Requires an interactive session; -p and Agent SDK sessions do not spawn teammates.
Dynamic Workflows (Workflow tool) An executed script drives fan-out across dozens to hundreds of subagents. The script keeps intermediate results outside the coordinator's context. The workflow tool is subject to the session's permission evaluation.
Managed Agents multiagent Session threads under one session. MCP servers are agent-scoped. Session vault_ids credentials apply to every thread. One delegation level, up to 20 predefined agents per list, and up to 25 child threads per session (advisor and workflow-run threads excluded). Workflow limits include 64 working threads at once (not guaranteed by the API). A run can start up to 1,000 agents over its lifetime. A session allows 10 open runs by default.

A structured handoff turns a worker's return value into a typed contract. In the Agent SDK, output_format / outputFormat accepts a JSON Schema. The SDK validates the output, retries when it does not match, and exposes valid data as ResultMessage.structured_output; repeated validation failure returns error_max_structured_output_retries.

Human-in-the-loop and approval flow

A human-in-the-loop (HITL) flow pauses a tool call for a human decision.

The Agent SDK evaluates each tool request through six ordered checks: hooks, deny rules, ask rules, permission mode, allow rules, then the canUseTool callback.

The order is the trap: a call approved at an earlier step — by acceptEdits, bypassPermissions, or an allow rule — never reaches canUseTool, so checks placed there are bypassed for that tool. Put mandatory checks on auto-approved tools in PreToolUse hooks. Permission modes include "default", "dontAsk", "acceptEdits", "plan", "auto", and "bypassPermissions". A subagent can inherit the main session's mode, overriding its own permissionMode, but Claude Code never applies bypassPermissions to a subagent.

canUseTool handles both tool-permission requests and clarifying questions via AskUserQuestion; execution pauses until the callback responds. Return allow with updatedInput in TypeScript or updated_input in Python, optionally with updated permissions, or deny with a message. AskUserQuestion is unavailable in subagents spawned via the Agent tool.

PreToolUse hooks run first and can enforce a policy before permission rules are evaluated. Hook decisions include allow, deny, ask, and defer; when hooks disagree, precedence is deny, defer, ask, then allow. SubagentStart and SubagentStop inputs include agent_id and agent_type. Set onFailure: "block" (on_failure="block" in Python) to block the action when a hook fails.

For approvals outlasting a process, non-interactive -p single-tool turns support deferred HITL: return defer, and the turn ends with stop_reason: "tool_deferred" while the pending call stays in the transcript. Resume the session later with --resume and let the hook handle the call again. In Managed Agents, a child thread's tool request can cross-post to the primary stream with session_thread_id; respond with user.tool_confirmation or user.custom_tool_result.

The block below is a Python reference skeleton, not a standalone runnable program: imports are omitted, and approved = False stands in for a real approval integration. With those pieces supplied, it wires bounded fan-out through SDK env caps, fork denial, a fail-closed Bash deny hook, human approval in canUseTool, and a schema on the return value.

class AuditReport(BaseModel):
    service: str
    critical_findings: list[str]
    requires_hotfix: bool


async def deny_bash_for_audit(input_data: dict, tool_use_id: str | None, context):
    if input_data.get("hook_event_name") == "PreToolUse":
        return {
            "hookSpecificOutput": {
                "hookEventName": "PreToolUse",
                "permissionDecision": "deny",
                "permissionDecisionReason": "Bash is disabled for this audit.",
            }
        }
    return {}


async def hitl_approval(
    tool_name: str, input_data: dict, context: ToolPermissionContext
) -> PermissionResultAllow | PermissionResultDeny:
    approved = False  # Replace with an async UI or Slack approval lookup
    if approved:
        return PermissionResultAllow(updated_input=input_data)
    return PermissionResultDeny(message=f"Human approval required before executing {tool_name}.")


async def run_audit():
    options = ClaudeAgentOptions(
        permission_mode="default",
        disallowed_tools=["Agent(fork)"],
        max_turns=25,
        max_budget_usd=3.50,
        env={
            "CLAUDE_AGENT_SDK_DISABLE_BUILTIN_AGENTS": "1",
            "CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH": "1",
            "CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS": "4",
        },
        agents={
            # AgentDefinition uses camelCase wire fields in Python.
            "service-auditor": AgentDefinition(
                description="Audits a single service directory for auth flaws.",
                prompt=(
                    "Audit only the assigned directory. Write detailed evidence to "
                    "/tmp/audit_notes.md if >500 words, return only critical flaws."
                ),
                tools=["Read", "Glob", "Grep"],
                model="sonnet",
                maxTurns=10,
                effort="medium",
            ),
        },
        hooks={
            "PreToolUse": [
                HookMatcher(matcher="Bash", hooks=[deny_bash_for_audit], on_failure="block"),
            ]
        },
        can_use_tool=hitl_approval,
        output_format={"type": "json_schema", "schema": AuditReport.model_json_schema()},
    )

    try:
        async for msg in query(
            prompt="Dispatch service-auditor subagents in parallel for services/auth and services/billing.",
            options=options,
        ):
            if isinstance(msg, ResultMessage):
                if msg.subtype == "success" and msg.structured_output:
                    print(AuditReport.model_validate(msg.structured_output).model_dump_json(indent=2))
                else:
                    print(f"Stopped: {msg.subtype}; cost=${msg.total_cost_usd}")
    except Exception as exc:
        print(f"Audit loop terminated: {exc}")


asyncio.run(run_audit())

Decision criteria

Pick the smallest design that answers the question, then confirm it with measurements.

  • Stay single-agent until you can name a trigger: subtasks noisy enough to pollute one window, genuinely independent branches, or a privilege boundary to enforce between agents. This is a recommendation, not a documented threshold.
  • Use subagents for bounded hub-and-spoke delegation where one parent reads every result.
  • Use Agent Teams only in interactive sessions where peers claim shared work and message each other; -p and SDK sessions do not spawn teammates.
  • Use Dynamic Workflows when fan-out reaches dozens to hundreds of items and loop state belongs in code rather than context.
  • Use Managed Agents multiagent when threads, budgets, and cancellation should be server-managed, accepting one delegation level and the beta's caps.

Before scaling a design, get whole-tree totals from ResultMessage.model_usage / modelUsage., the ResultMessage.subtype that says why a run ended., per-thread events for workflow runs., and a baseline separating token effects from topology effects, as Anthropic's 80% variance result illustrates..

Failure modes and recovery

Failure mode Root cause Detection signal Containment and recovery
Runaway fan-out or recursion Orchestrator over-spawns or nests deeply. Rising modelUsage spend; Concurrent subagent limit reached. Cap spawn depth, concurrency, and spend; scale effort to task difficulty.
Handoff "telephone game" Role-split chain re-summarizes shared context; large outputs transit the coordinator. Downstream requirement drift; bloated coordinator context. Group by context boundary, store artifacts and return refs, enforce schemas.
Report-borne prompt injection Subagent relays instruction-shaped text from untrusted content it read. [harness: subagent output matched instruction-shaped pattern(s): ...] marker. Keep output scanning, least-privilege tools / disallowedTools, PreToolUse hooks; reject approvals relayed by an agent.
Verification early victory Verifier stops after one or two smoke tests. "Pass" reported while edge cases are broken. Require the full suite and negative tests in the prompt; re-run deterministic tests in a completion hook.
Silent canUseTool bypass Policy sits in canUseTool; the tool was approved earlier in the order. Unprompted execution; the CLAUDE_SDK_CAN_USE_TOOL_SHADOWED warning. Move guards to PreToolUse with on_failure="block", or deny outright via disallowed_tools.
HITL process hang A pending canUseTool callback pauses execution until a response. Serverless or CI runner stalled with no approval UI Return defer in a -p single-tool turn and --resume later; answer requires_action asynchronously in Managed Agents.
Partial or silent worker failure API error, rate limit, or maxTurns cut the worker off. Foreground partial text or Agent terminated early...; background failure notice. Read per-thread events and ResultMessage.subtype; configure fallback model chains; resume or retry idempotent tools.
Shared-workspace edit collision Concurrent agents mutate the same files. Overwritten edits and merge conflicts Give writers isolation: worktree or partition file ownership; never mark a mutating custom tool readOnlyHint.

Agent errors can compound across steps. For deployments, Anthropic describes rainbow deployments: shift traffic gradually from old to new versions while both remain available, which avoids disrupting running agents. Worker failures should be surfaced and handled: a background subagent can be marked failed with the API error and its last output attached; a configured fallback model can switch models mid-run.

Common mistake Treating canUseTool as the security boundary

It is the last check, not the only one. acceptEdits, bypassPermissions, and allow rules approve calls before canUseTool runs; put non-negotiable enforcement in PreToolUse hooks with onFailure: "block" or in deny rules.

Common mistake Assuming a subagent's permissionMode restricts a permissive parent

A parent in acceptEdits mode can override the subagent's own permissionMode, so setting the subagent to default does not prevent automatic approval of file edits.

Common mistake Reading a finished workflow run as a clean run

Managed Agents reruns a failed agent once on a new thread and lets the program decide whether a second failure ends the run, so a completed run can still contain failures; inspect per-thread events.

Exam lens

Exam lenseditorial inference

  • Telephone-game chain: when a planner, coder, tester, reviewer pipeline drifts or overspends, consolidate tightly coupled work into context-centric agents and isolate only independent slices or black-box verification.
  • Deterministic guardrails: a policy check beside allowed_tools or under a permissive parent is bypassed; enforcement moves to PreToolUse with on_failure="block" and to disallowed_tools.
  • Transport choice: Subagents for bounded hub-and-spoke delegation, Agent Teams only for interactive peer work, Dynamic Workflows for fan-outs of dozens to hundreds of items.
  • Async HITL and surgical cancellation: defer plus --resume avoids holding a process open through an approval; user.interrupt with session_thread_id targets one worker.

Self-check

QA parent in acceptEdits spawns a subagent whose AgentDefinition sets permissionMode to default. Do Edit calls reach canUseTool?Show answer
A

No. The subagent inherits acceptEdits from the parent, so Edit is auto-approved before step 6. Gate it with a PreToolUse hook instead.

QWhy should you benchmark rather than assume twenty concurrent subagents improve throughput?Show answer
A

The concurrency cap defaults to 20 workers, but the cap does not guarantee that 20 workers improve throughput. Read-only tools can run concurrently while Edit, Write, and Bash run sequentially within a turn. A synchronous wave still waits on its slowest worker. Measure concurrency under representative load.

QHow do you pause a headless single-tool run for an approval taking hours without holding the process open?Show answer
A

Return permissionDecision: "defer" from a PreToolUse hook; the tool does not run and the turn ends with stop_reason: "tool_deferred" and the pending call in the transcript. Resume that session with --resume once the decision arrives.
